# A1-2 실행 안정화 및 평가 보완 설계

## 목표

A1-2 여행 플래너를 현재 설정된 `gpt-5.6-luna` 모델로 실제 실행하고, 사전평가에서 지적된 재시도·검색 추상화·캐시·도시 입력 보정·문서화 부족을 최소 변경으로 보완한다.

## 설계

- OpenAI 요청 payload는 GPT-5 계열에서 지원되지 않는 `temperature`를 생략하고, 기존 모델에서는 필요할 때만 유지한다.
- 추천 JSON 검증은 필수 키·타입뿐 아니라 `events` 1~3개, `reason` 2~4문장을 확인한다.
- JSON 파싱/검증 오류만 1회 재시도하고, HTTP·인증·쿼터 오류는 별도 오류로 기록한다.
- Kakao 호출은 `PlaceSearchProvider` 인터페이스 뒤에 두고, 현재 구현은 `KakaoPlaceSearchProvider` 하나만 제공한다.
- 도시명은 공백과 `시`, `특별시` 등의 표기를 보수적으로 정리한다.
- 동일 날짜의 완전한 raw JSON이 있으면 유효성 확인 후 재사용하고, 손상·날짜 불일치·필수 키 누락이면 정상 API 흐름으로 돌아간다.
- 결과 저장 실패는 `OUTPUT_WRITE_ERROR`로 기록하되, API 키나 응답 원문은 오류에 남기지 않는다.

## 검증 기준

- 표준 라이브러리 unittest와 `py_compile`이 통과한다.
- `--help`, 잘못된 날짜, 키 누락 동작이 유지된다.
- 실제 실행 후 날짜별 raw JSON과 Markdown이 생성된다.
- Kakao 0건/API 오류에도 Markdown이 생성되고 `데이터 없음`과 `errors`가 남는다.
- 결과·문서·Git 변경에 실제 비밀값이 없다.
