# A1-2 Pre-submission Checklist

제출 전에는 이 문서를 기준으로 실제 파일과 README 내용을 대조한다.

## 1. 원문 요구사항 확인

- [ ] 미션 원문을 다시 읽었다.
- [ ] 필수 산출물을 모두 표시했다.
- [ ] 선택/보너스 과제를 필수와 분리했다.
- [ ] 제출 방식, 파일명, 폴더명 조건을 확인했다.
- [ ] 금지 조건이나 제한 조건을 확인했다.

## 2. 기능 요구사항 확인

- [ ] 필수 기능이 모두 구현됐다.
- [ ] 입력 예외 상황을 처리한다.
- [ ] 출력 형식이 미션 요구와 맞다.
- [ ] 데이터 저장 또는 파일 생성 요구가 있으면 실제로 동작한다.
- [ ] 보너스 기능은 실제 구현한 것만 문서에 적었다.
- [ ] raw JSON만 남은 같은 날짜를 재실행해 API 호출 없이 Markdown이 재생성되는지 확인했다.
- [ ] LLM Markdown에 필수 섹션이 없을 때 fallback 리포트로 대체되는지 확인했다.

## 3. 문서 확인

- [ ] README에 미션명과 목적이 적혀 있다.
- [ ] README의 실행 방법을 그대로 따라 하면 실행된다.
- [ ] 주요 기능 목록이 실제 구현과 일치한다.
- [ ] 요구사항 대응표가 있다.
- [ ] 스크린샷 또는 실행 결과가 필요한 경우 포함했다.
- [ ] 참고 링크는 실제 존재하는 링크만 적었다.

## 4. AI 결과 검토

- [ ] 원문에 없는 조건을 만들어내지 않았다.
- [ ] 필수 산출물을 빠뜨리지 않았다.
- [ ] 기능 요구사항을 잘못 해석하지 않았다.
- [ ] 모호한 부분을 단정하지 않았다.
- [ ] 어려운 개념은 쉬운 말로 풀어 썼다.
- [ ] 참고자료 링크를 지어내지 않았다.

## 5. 실행 및 검증

- [ ] 프로그램 실행을 확인했다.
- [ ] 문법 검사를 했다.
- [ ] 필요한 테스트를 실행했다.
- [ ] 생성 파일이 올바른 위치에 만들어지는지 확인했다.
- [ ] 오류 메시지가 사용자에게 이해 가능하게 나온다.

## 6. Git 확인

- [ ] `git status`로 변경 파일을 확인했다.
- [ ] 불필요한 임시 파일이 없다.
- [ ] 제출 대상 파일이 모두 추적 대상에 포함됐다.
- [ ] 필요한 경우 커밋 메시지를 기능 단위로 작성했다.

## 7. 최종 제출 판단

- [ ] 원문 기준으로 필수 조건을 모두 만족한다.
- [ ] 실행 방법과 실제 실행 결과가 일치한다.
- [ ] 과장된 설명 없이 구현한 내용만 설명한다.
- [ ] 제출자가 직접 이해하고 설명할 수 있는 상태다.
