# A1-3 서비스 기획서

## 1. 서비스 개요

- 서비스명: AX Ground
- 한글 표기: AX그라운드
- 브랜드 운영 방식: 회사명이나 개인명을 전면에 내세우지 않는 독립 브랜드
- 명칭 검토 상태: KIPRIS 완전일치 검색에서는 동일 명칭을 찾지 못했으나, 유사 출원 `AX IS GROUND`가 확인되어 실제 상용화·상표 출원 전 추가 검토 필요
- 서비스 설명: 기업·기관·학교의 현장에 맞는 AI 교육과 실행 가능한 AX 로드맵을 제공합니다. Hero 메인 카피로 쓰지 않고 하위 서비스 설명에 활용할 수 있다.
- 서비스 목적: 조직의 업무와 학습 환경을 진단하고, 맞춤형 AI 교육부터 AX 로드맵과 AI 도구·MVP 제작까지 실제 실행으로 연결한다.
- 타겟 사용자: AI 교육이나 AX 컨설팅을 찾는 중소기업 실무팀, 기관 담당자, 학교·교육기관 담당자, 일반 직장인
- 사용자가 얻는 가치: 간단한 AI 진단으로 현재 상황과 우선 과제를 파악하고, 조직에 맞는 교육·컨설팅 방향을 확인한 뒤 실제 상담으로 이어갈 수 있다.

### 첫 화면 핵심 문구

- Hero 헤드라인: `AI 교육부터 자동화, AX 전환까지 / 목표에 더 빠르게 도달하고 싶으신가요? / AX Ground가 함께합니다.`
- 설명: `반복 업무는 자동화하고, 학습과 실행은 가속화합니다. AX Ground는 AI 교육부터 업무 진단, 자동화 흐름 설계, AX 로드맵까지 실제 실행으로 연결합니다.`
- Hero CTA: Primary `AI·AX 진단 시작하기`, Secondary `맞춤 상담 문의`
- Hero Workflow: 업무 입력 → AI 분석·분류 → 이메일·알림/문서·보고서/담당자·업무도구 분기 → 결과 정리 → 교육·자동화·AX 실행 방향
- 표현 원칙: Node와 Connector로 자동화 흐름을 설명하되 n8n UI를 복제하지 않는다. Figma에는 Node 구조와 `[SCROLL INTERACTION]` Annotation만 있으며, 구현은 스크롤에 따라 노드→연결선이 순차 생성되는 모션으로 반영했다.
- 서비스의 실행 서사: 배우고 → 업무를 진단하고 → 자동화하고 → AX로 확장한다. 기술적이되 일반 기업·기관 담당자도 이해할 수 있는 표현을 쓴다.
- Desktop 배치 확정: 카피·CTA를 위에 두고 Workflow는 아래에서 화면 너비를 넓게 사용한다. 전달문 #2의 명시적인 상하 구조를 기준으로 하며 #6의 “오른쪽”은 좌우 2열 배치로 적용하지 않는다.
- 기존 `현장에 맞는 AI 교육과 실행 가능한 AX 로드맵` 문구는 하위 서비스 설명에서 활용할 수 있다.

## 2. 문제 정의

- 사용자가 겪는 문제: 자신의 조직·업무에 어떤 AI 교육이나 AX 접근이 적합한지, 무엇부터 시작해야 하는지 판단하기 어렵다.
- 기존 방식의 불편함: 일반적인 AI 도구 소개만으로는 실제 업무 적용 순서와 교육 이후의 실행 방법을 정하기 어렵고, 교육·업무 진단·도구 제작을 서로 다른 곳에서 알아봐야 한다.
- 이 서비스가 해결하는 방식: 짧은 AI·AX 실행 준비도 진단으로 현재 상태와 우선순위를 정리하고, 맞춤형 AI 교육안과 AX 실행 로드맵을 제안한 뒤 필요한 경우 상담과 실제 실행 지원으로 연결한다.

### Home 고객 문제 제기

- AI 교육을 하고 싶은데 무엇을 가르쳐야 할지 모르겠다.
- AI 도구를 사용하지만 실제 업무 방식은 크게 달라지지 않았다.
- 반복 업무를 자동화하고 싶지만 어디서 시작할지 모르겠다.
- AX를 추진하고 싶지만 실행 순서와 방향을 모르겠다.

### 진단과 빠른 상담의 역할

- AI·AX 진단: 필요한 것이 무엇인지 아직 모르는 방문자에게 8개 문항으로 상황을 파악하고 추천 방향을 제시한다.
- 빠른 상담: 필요한 지원을 대략 알고 있는 방문자가 긴 진단 없이 이메일로 상담을 요청한다.
- 빠른 상담은 질문 기반 AI 진단을 실행하지 않는다. 결과 이메일/상담 폼과 수집 목적을 구분한다.
- 빠른 상담 개인정보 안내 문구는 확정하지 않고 Figma에서 `[법적 문구 검토 필요]`로 표시한다.

### Home 흐름

`Header → Hero → Customer Problems → Core Services → AI·AX 맞춤 진단 → 진행 방식 → 빠른 상담 → Trust/Cases → FAQ → Final CTA → Footer`

빠른 상담은 진행 방식 뒤, Trust/Cases 앞에 둔다. Trust/Cases에는 확인된 자료만 쓰며 검증되지 않은 고객 사례·성과 수치를 만들지 않는다.

## 5. AI 기능 설계

- AI 기능 이름: AI·AX 실행 준비도 진단
- 사용자 입력: 8개 문항(선택 4개 + 자유 입력 4개). 입장, AI 활용 단계, 우선 목표, 적용 대상, 개선 희망 업무, 빈도·소요, 자료·시스템 환경, 시작 시기·성공 기준을 묻는다. PRD의 9개 주제 중 "개선 업무 + 업무 기회도"를 한 문항으로 병합해 8문항으로 구성했다.
- 요청 흐름: `diagnosis.html`의 답변을 `fetch('/api/diagnose')`로 전송 → `api/diagnose.py`가 서버에서 다시 검증 → 규칙 평가 + AI 설명 생성 → JSON 응답 → 결과 8개 블록으로 화면 표시. 결과는 이메일 입력 없이 먼저 확인하고, 결과 아래 후속 패널에서 결과 이메일·맞춤 상담을 선택한다(접수 API는 미구현).
- 평가 영역: 목표 명확도, 인력·교육 준비도, 업무 기회도, 데이터·기술 준비도, 보안·운영 준비도
- 결과 생성: 규칙 기반 평가(`api_services/diagnosis_rules.py`)로 영역별 참고 점수(1~5)와 추천 경로를 계산하고, AI API(`api_services/ai_provider.py`)가 답변에 근거한 설명·교육안·AX 후보·실행 로드맵을 생성한다. 점수·경계값은 초기안이며 정식 컨설팅 기준이 아니다.
- AI 출력(결과 8블록): 현재 상태 요약, 5개 영역 평가, 우선 해결 과제, 추천 시작 경로, 맞춤형 AI 교육안, 업무 진단·AX 적용 후보, 3단계 실행 로드맵, 주의사항·추가 확인, 상담 연결
- 사용자에게 제공할 가치: 무엇을 먼저 배울지와 어떤 업무부터 작게 검증할지를 짧은 시간 안에 확인하고 상담 전 논의할 내용을 정리할 수 있다.
- 사용할 AI API: OpenAI 호환 게이트웨이 `https://copa.codyssey.kr/v1/chat/completions`, 모델 `gpt-5.5`. `reasoning_effort`는 사용하지 않는다(게이트웨이 미지원 확인). 키는 `AI_API_KEY` 환경 변수로만 읽고, 공급자 교체를 위해 어댑터 경계를 둔다.
- 운영 기본값(구현됨): 자유 입력 문항당 최대 500자, 요청 본문 16 KiB, AI 요청 타임아웃 20초, 8초 뒤 진행 안내, 브라우저 전체 타임아웃 25초. 자동 재시도는 하지 않고 사용자가 직접 재시도한다. 호출 비용 상한은 월 예산 결정 후 설정한다(미정).
- 개인정보 처리: 이름, 이메일, 회사명은 AI API에 전달하지 않는다. 후속 패널의 연락처는 결과 화면 이후 선택 입력이며 접수 API 연동 전이다.
- 저장 기준: 후속 요청이 없는 익명 진단 답변·결과는 저장하지 않는다. 향후 비식별 집계 통계를 위해 확장 지점만 남기고 기본 비활성으로 둔다.

## 7. 기술 스택

- 프론트엔드: HTML, CSS, JavaScript
- 백엔드: Vercel Serverless Functions, Python
- 배포: GitHub, Vercel
- 선택 UX: 다크 모드
- 다크 모드 기본값 제안: 첫 방문은 시스템 설정을 따르고, 사용자가 고른 테마를 브라우저에 저장한다. 주요 화면과 오류·포커스 상태의 대비를 확인한다.
- 데이터베이스: Neon PostgreSQL (선택 확정, 이번 단계 미구현)
- AI API: OpenAI 호환 게이트웨이(`copa.codyssey.kr`), 모델 `gpt-5.5`
